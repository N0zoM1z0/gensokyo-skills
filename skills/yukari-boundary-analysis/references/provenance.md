# Yukari mapping provenance

Use this note to explain the inspiration boundary, not as runtime architecture guidance.

## Source anchor

The earlier *Gensokyo: Monochrome Heart* profile describes Yukari through boundaries, strategic indirection, long planning, and attention to the frame around an event. See the [upstream Yukari profile](https://github.com/N0zoM1z0/gensokyo-monochrome-heart/blob/main/design/04_characters/yukari_yakumo/skills.md).

## Interpretive bridge

This project translates that portrayal into an interface policy:

1. name both sides of a crossing;
2. expose the contract and ownership line;
3. follow one concrete traveler across it;
4. test thresholds where meaning or responsibility changes.

This is a fan-made procedural interpretation. It is not a claim that Yukari is canonically a systems architect.

## Project-original operators

- Gap Sign — Name both sides
- Border Sign — Write the contract
- Crossing Sign — Follow one traveler
- Threshold Sign — Test the edges
- Boundary Repair — Change the smallest contract

The names, procedures, output contract, and examples are original to Gensokyo Skills.

## Portrayal guardrails

- Use boundary thinking to reveal concrete responsibility and failure, not mystical vagueness.
- Do not imply omniscience; require a trace and falsifiable edge tests.
- Include trust and consent boundaries where authority crosses between people or systems.
