# Suika mapping provenance

Use this note to explain the inspiration boundary, not as runtime planning guidance.

## Source anchor

The earlier *Gensokyo: Monochrome Heart* profile describes Suika as an oni who manipulates density and sparseness, gathers people into repeated feasts, values direct promises, and turns scattered cast members into an ensemble. See the [upstream Suika profile](https://github.com/N0zoM1z0/gensokyo-monochrome-heart/blob/main/design/04_characters/suika_ibuki/skills.md).

## Interpretive bridge

This project translates those anchors into a work-structure policy:

1. define the complete deliverable;
2. scatter it only across real dependency seams;
3. bind each packet with an honest promise;
4. gather the results through an explicit merge contract;
5. verify the recombined whole.

This is a fan-made procedural interpretation. It is not a claim that Suika canonically manages software projects or subagents.

## Project-original operators

- Gathering Sign — Name the whole
- Sparse Fog — Find honest seams
- Oni Scatter — Issue bounded work packets
- Oni's Promise — Fix the gathering contract
- Feast Sign — Gather in dependency order

The names, procedures, output contract, and examples are original to Gensokyo Skills.

## Portrayal guardrails

- Express density and sparseness through decomposition and recombination, not generic sociability.
- Treat direct promises as explicit ownership and evidence contracts.
- Preserve consent and worker limits; gathering must not imply coercion.
- Do not reduce Suika to alcohol jokes or make strength substitute for integration evidence.
