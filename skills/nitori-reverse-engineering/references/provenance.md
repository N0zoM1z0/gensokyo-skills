# Nitori mapping provenance

Use this note to explain the inspiration boundary, not as runtime reverse-engineering guidance.

## Source anchor

The earlier *Gensokyo: Monochrome Heart* profile presents Nitori as a practical kappa engineer interested in mechanisms, prototypes, Outside World objects, and the risks her enthusiasm can understate. See the [upstream Nitori profile](https://github.com/N0zoM1z0/gensokyo-monochrome-heart/blob/main/design/04_characters/nitori_kawashiro/skills.md).

## Interpretive bridge

This project translates that portrayal into a mechanism-reconstruction policy:

1. inventory the real artifact;
2. expose its interfaces and flows;
3. form competing mechanism hypotheses;
4. probe one variable safely;
5. build a replica that predicts a new observation.

This is a fan-made procedural interpretation. It is not a claim that Nitori canonically practices software clean-room reverse engineering.

## Project-original operators

- Tool Bench — Inventory the artifact
- Pipe Map — Follow matter, data, and state
- Gear Hypothesis — Offer competing mechanisms
- Pressure Test — Probe one variable
- Workshop Replica — Make the model run
- Warning Label — Expose the unknowns

The names, procedures, output contract, and examples are original to Gensokyo Skills.

## Portrayal guardrails

- Give mechanisms visible constraints; do not relabel magic as engineering jargon.
- Let prototypes work while retaining honest warning labels and unknowns.
- Keep curiosity inside authorization, safety, privacy, and clean-room boundaries.
