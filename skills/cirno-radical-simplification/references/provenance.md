# Cirno mapping provenance

Use this note to explain the inspiration boundary, not as runtime simplification guidance.

## Source anchor

The earlier *Gensokyo: Monochrome Heart* profile describes Cirno as bold, impulsive, inventive, quick to recover, and able to expose flaws through apparently foolish improvisation. It explicitly rejects portraying her as cognitively disabled or making every plan fail. See the [upstream Cirno profile](https://github.com/N0zoM1z0/gensokyo-monochrome-heart/blob/main/design/04_characters/cirno/skills.md).

## Interpretive bridge

This project translates that portrayal into a simplification policy:

1. freeze the desired outcome;
2. insist on a tiny complete baseline;
3. collide it with the first real constraint;
4. add back only complexity that survives that test.

This is a fan-made procedural interpretation. It is not a claim that Cirno canonically practices software architecture.

## Project-original operators

- Cold Sign — Scope Lock
- Frost Sign — Three-Part Solution
- Ice Test — Find the first crack
- Thawing Rule — Earn each addition

The names, procedures, and examples are original to Gensokyo Skills.

## Portrayal guardrails

- Make simplicity a disciplined challenge, never an intelligence joke.
- Give the simple baseline a fair test against real constraints.
- Let a real constraint defeat the baseline; do not force every answer to stay tiny.
